# 功能需求现状修订稿

以下文本根据当前仓库实现情况修订，可用于替换原来的八项功能描述。修订重点是避免把尚未完整自动化的能力写成已经完全具备，同时明确签名验证、多签验证、交易上下文消费范围和差分测试的边界。

## 建议修改稿

（1）字节码执行功能：系统支持执行编译生成的双栈虚拟机字节码。执行系统维护主栈、副栈、字节码位置、调用栈、函数执行范围和运行状态，支持脚本数据处理、栈操作、算术比较、逻辑控制、哈希计算、验证失败处理和错误报告。对于签名验证，字节码虚拟机提供单签验证回调机制；非交互式运行器在未配置真实签名验证回调时不会默认通过签名校验。多签真实验证目前仍属于限制项。字节码执行结果能够反映执行状态、主栈与副栈状态、错误信息、执行统计信息，并可按需导出执行轨迹。

（2）交易上下文功能：系统支持加载并表示交易上下文数据，能够处理交易版本、锁定时间、输入数量、输出数量、解锁输入、输入哈希、输出哈希以及部分可派生字段。交易上下文可通过文本或 JSON 文件传入。源码解释路径和字节码执行路径共享部分 BVM 交易元数据，但两条路径的消费范围并不完全相同：源码解释路径还可以消费函数参数、合约实例字段和运行时对象字段；字节码执行路径主要消费虚拟机交易元数据。对于签名验证场景，系统明确区分本地模拟结果和真实验证结果边界：AST 解释路径通过显式配置的模拟结果表达签名校验结果，字节码路径通过验证回调接入真实签名验证。

（3）源语言解释功能：系统支持直接解释 `.ct` 合约源码中的已实现 AST 语义子集，包括变量声明、赋值、表达式、函数调用、私有函数、合并后的库函数、结构体、数组、字段访问、索引访问、条件语句、循环语句、多返回值、解构赋值和返回语句。解释系统能够返回运行结果，并在运行时错误发生时报告错误类型、错误信息和对应源码位置。需要注意的是，AST 解释器面向调试、测试和语义对照场景，并不等同于完整链上脚本验证器。

（4）运行时环境功能：系统提供运行时值系统、作用域链、函数帧、合约成员对象和内置对象。运行时环境能够管理变量值、字段值、函数调用、合约实例对象、虚拟机内置对象和错误传播，用于在源码解释阶段统一表示源码层状态，并为调试、测试和与底层栈状态的对照提供基础。

（5）编译支撑功能：系统继续支持将 `.ct` 源文件转换为双栈虚拟机字节码。编译过程包括源码读取、导入处理、词法分析、语法分析、语义分析、所有权预检查、静态信息生成、常量折叠、字节码生成、字节码处理和结果导出。该功能为字节码执行、调试信息生成、执行轨迹导出和后续差分测试提供输入。

（6）调试功能：系统支持源码级断点、函数断点、单步进入、单步跳过、跳出函数、继续执行、栈查看、调用栈查看、字节码查看和交易上下文加载。命令行调试器能够把当前字节码位置映射回源码行，并向开发者展示主栈与副栈状态。实时调试服务通过 JSONL 协议向可视化插件提供虚拟机快照、断点、单步、继续执行、变量查看和调用栈等调试能力。

（7）插件可视化功能：系统配套 VS Code 可视化插件，支持打开执行轨迹文件，展示源码、字节码位置、当前指令、主栈、副栈、执行前后状态、栈元素变化和诊断信息。插件支持离线回放调试和实时虚拟机调试；在保存合约后，可根据配置重新生成执行轨迹并刷新可视化结果，或重启实时虚拟机调试会话。

（8）差分测试支撑功能：系统具备开展差分测试的基础能力，即同一合约可以分别通过源码解释路径和字节码执行路径运行，并获得运行状态、返回值或栈状态、错误信息、执行步数、源码位置和执行轨迹等可比较信息。目前仓库中尚未提供独立的一键差分测试命令或完整自动对比框架；现阶段差分测试可通过脚本组合 `ast` 与 `run` 两个入口实现。后续可在此基础上补充自动化比较逻辑，用于比较执行成功与否、错误类型、返回值或主栈栈顶、副栈状态、执行步数、源码位置和验证失败位置，从而发现解释执行系统、编译器或虚拟机之间的语义偏差。

## 简短版结论

当前系统已经具备字节码执行、交易上下文加载、源码解释、运行时环境、编译支撑、命令行调试和插件可视化等主要能力；但差分测试目前更准确地说是“具备支撑能力”，尚不是完整内置功能。签名验证也需要区分 AST 模拟结果、字节码单签回调和未完成的多签真实验证边界。
