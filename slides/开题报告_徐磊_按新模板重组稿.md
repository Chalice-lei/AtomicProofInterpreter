### 学位申请成果摘要和关键词

摘要：随着区块链技术由数字资产转向复杂业务协作场景，智能合约已成为去中心化系统中实现状态管理、规则约束和价值转移的重要技术基础。现有智能合约执行环境主要围绕以太坊账户模型和 EVM 展开，而 UTXO 模型在交易并行性、状态隔离和可验证性方面具有自身优势。对于面向 UTXO 模型的智能合约系统，如何在高级语言、字节码和双栈虚拟机之间建立可解释、可调试、可验证的执行链路，是提升合约开发效率和工程可靠性的关键问题。

本课题依托 UTXO_Interpreter 工程载体，围绕 UTXO 双栈虚拟机环境下智能合约解释性执行系统的设计与实现开展研究。系统拟支持源代码到抽象语法树、字节码到双栈虚拟机执行两个层次的解释运行，围绕词法分析、语法分析、语义检查、字节码生成、虚拟机模拟、交易上下文注入、运行状态跟踪、调试交互和测试验证等环节构建完整执行流程。通过该系统，开发者能够在合约部署前观察表达式求值、变量绑定、栈状态变化、交易参数传递和执行错误定位过程，从而降低 UTXO 智能合约开发与调试成本。

在研究方法上，本课题拟采用编译原理、解释器设计、虚拟机执行模型、模块化软件设计和测试驱动验证等方法，对 UTXO 合约执行过程中的语义表示、运行时环境、双栈执行机制和交互式调试能力进行系统设计。系统实现将重点解决高级语言语义到字节码执行之间的信息衔接、链上交易上下文在本地解释环境中的模拟、源码级与字节码级执行结果的一致性验证，以及面向典型合约样例的回归测试问题。

预期成果包括一套面向 UTXO 双栈虚拟机的智能合约解释性执行系统、相应的命令行与交互式调试工具、典型合约测试样例、系统设计与测试文档以及学位申请成果论文。该成果可为 UTXO 模型下智能合约语言工具链建设、合约开发调试和执行语义验证提供工程支撑，具有一定的软件工程应用价值和技术探索意义。

关键词：UTXO 智能合约；双栈虚拟机；解释执行

Abstract: With the development of blockchain technology from digital assets to complex business collaboration scenarios, smart contracts have become an important technical basis for implementing state management, rule constraints and value transfer in decentralized systems. Existing smart contract execution environments mainly focus on the Ethereum account model and the EVM, while the UTXO model has advantages in transaction parallelism, state isolation and verifiability. For smart contract systems based on the UTXO model, establishing an interpretable, debuggable and verifiable execution chain among high-level languages, bytecode and a dual-stack virtual machine is essential for improving development efficiency and engineering reliability.

This project is based on the UTXO_Interpreter engineering prototype and studies the design and implementation of an interpretive execution system for UTXO smart contracts on a dual-stack virtual machine. The system is intended to support two levels of execution: source-code-to-AST interpretation and bytecode execution on a dual-stack virtual machine. It integrates lexical analysis, syntax analysis, semantic checking, bytecode generation, virtual machine simulation, transaction context injection, runtime state tracing, interactive debugging and test verification into a complete execution workflow. With this system, developers can observe expression evaluation, variable binding, stack state changes, transaction parameter passing and execution error localization before contract deployment.

The project adopts methods from compiler construction, interpreter design, virtual machine execution models, modular software design and test-driven verification. It focuses on runtime semantic representation, environment management, dual-stack execution mechanisms and interactive debugging capabilities. The implementation will address the connection between high-level language semantics and bytecode execution, the simulation of on-chain transaction context in a local interpretation environment, consistency checking between source-level and bytecode-level execution, and regression testing based on typical contract examples.

The expected outcomes include an interpretive execution system for UTXO smart contracts on a dual-stack virtual machine, command-line and interactive debugging tools, typical contract test cases, system design and testing documents, and a degree application report. The results are expected to support toolchain construction, contract development and debugging, and execution semantics validation for UTXO-based smart contract languages.

Keywords: UTXO Smart Contract; Dual-Stack Virtual Machine; Interpretive Execution

## 二、选题依据

### 1. 研究背景与研究意义

区块链系统通过密码学、分布式共识和可验证数据结构实现可信执行环境，智能合约则进一步将业务规则、资产流转条件和状态变更逻辑编码为可自动执行的程序。比特币提出的 UTXO 模型以交易输出为状态载体，强调状态隔离、并行验证和可追溯性；以太坊进一步推动了通用智能合约平台的发展，使智能合约逐渐成为区块链应用的核心组件[1][2][4]。然而，不同账本模型下的智能合约执行方式存在显著差异。账户模型通常以全局状态和虚拟机指令序列为中心，而 UTXO 模型强调交易输入、交易输出、解锁条件和局部状态转移，合约执行过程更依赖交易上下文、脚本约束和验证逻辑之间的精确匹配。

在工程实践中，UTXO 智能合约开发面临较高的理解和调试门槛。开发者不仅需要关注高级语言语法和业务逻辑，还需要理解合约编译后的字节码结构、双栈虚拟机的执行行为、交易参数注入方式以及执行失败时的错误定位路径。如果缺少解释性执行、状态可视化和交互式调试工具，合约问题往往只能在编译后或链上执行阶段暴露，容易增加开发成本、测试成本和安全风险。因此，构建面向 UTXO 双栈虚拟机的智能合约解释性执行系统，能够在合约部署前提供本地执行、语义观察、状态追踪和错误定位能力，对提升合约开发效率和工程可靠性具有直接意义。

本课题的研究意义主要体现在三个方面。第一，在工程应用层面，系统能够为 UTXO 智能合约提供从源代码到字节码再到虚拟机执行的本地调试链路，帮助开发者在部署前发现语义错误、参数错误和运行时状态异常。第二，在技术方法层面，课题围绕 AST 解释执行、字节码解释执行、双栈状态模拟、交易上下文注入和执行结果一致性验证等问题开展设计，有助于完善 UTXO 合约工具链中的解释运行与调试能力。第三，在学位申请成果层面，课题具有明确的软件工程对象、可实现的系统边界、可测试的功能目标和较完整的工程工作量，符合专业学位研究生开题报告应体现实践价值、技术难度、工作量和可验证成果的要求。

### 2. 国内外概况与发展趋势

从智能合约发展脉络看，Szabo 较早提出了智能合约概念，强调通过程序化规则实现数字化协议执行[4]；比特币系统以 UTXO 模型和脚本机制支持有限的条件化资产转移[1]；以太坊则通过账户模型和 EVM 支持图灵完备的智能合约运行环境，形成了 Solidity、EVM、调试器、测试框架和安全分析工具等较成熟的生态[2][3]。围绕 EVM 的研究已经覆盖形式化语义、安全漏洞分析和执行验证等方向，例如 KEVM 对 EVM 进行了形式化建模，为合约执行行为的精确定义和验证提供了参考[13]；相关安全研究也系统总结了以太坊智能合约中的重入、异常处理、时间依赖和状态不一致等问题[11][12]。

与账户模型相比，UTXO 及其扩展模型在智能合约表达能力方面经历了从简单脚本到更高层合约语言的演进。Simplicity 试图为区块链构建更可分析的合约语言，强调语义简洁性与可验证性[5]；Move 语言通过资源类型和所有权约束提升资产语义表达的安全性，对智能合约语言设计提供了重要启发[6]。近年来，围绕 EUTxO、UTXO 上丰富合约表达和形式化验证的研究不断增加，相关工作关注 UTXO 账本模型中的合约结构、状态表达、编译正确性和验证挑战[14][16][17][18][20]。这些研究说明，UTXO 模型下的智能合约开发正在从简单脚本执行走向更复杂的高级语言、编译工具链、形式化语义和工程化调试支持。

国内相关工作主要集中在区块链平台研发、智能合约安全分析、虚拟机执行环境、合约语言工具链和行业应用落地等方面。原开题报告已经围绕 UTXO 智能合约执行、双栈虚拟机和解释器工程实现进行了初步论述，但对国内外研究现状的整理仍存在综述意识不足的问题，主要表现为国外代表性研究、国内工程实践、工具链生态和本课题切入点之间的关系尚未充分展开。按照开题培训材料要求，研究现状部分不宜仅罗列若干文献或技术名词，而应说明研究对象的发展过程、当前主流技术路线、已有研究的不足以及本课题拟解决问题的相对位置。

综合现有研究可以看出，智能合约技术正在呈现三个发展趋势。第一，合约语言从底层脚本和单一虚拟机接口向高级语言、强类型语义和可验证编译方向发展。第二，执行环境从链上部署后的黑盒执行向部署前本地解释、模拟执行、状态追踪和调试工具链方向发展。第三，安全保障从单点漏洞检测向编译、执行、测试和形式化验证相结合的全流程质量保障方向发展。本课题面向 UTXO 双栈虚拟机建立解释性执行系统，正是对上述趋势中“本地解释执行与调试工具链不足”问题的回应。

### 3. 选题的先进性与实用性

本课题的先进性主要体现在研究对象和系统目标的结合方式上。现有成熟工具链更多围绕账户模型和 EVM 展开，而本课题将解释性执行系统置于 UTXO 模型和双栈虚拟机环境中，关注交易上下文、双栈状态、字节码执行和源代码语义之间的对应关系。该设计不仅面向合约执行结果，还关注执行过程本身的可观察性和可调试性，能够为后续一致性验证、安全检查和形式化分析提供工程基础。

本课题的实用性主要体现在软件工程应用场景明确。系统建成后，可用于 UTXO 智能合约开发阶段的本地调试、测试样例运行、运行时错误定位、字节码执行行为观察和合约执行过程教学展示。对于企业实践场景而言，该系统能够在合约上链前提前发现输入构造、状态转移和执行逻辑中的问题，从而降低联调和部署成本。对于学术研究而言，该系统能够为 UTXO 合约语言工具链、解释器设计和执行语义验证提供可运行的实验平台。

### 4. 技术难度与工作量

本课题不是对已有解释器功能的简单封装，而是围绕 UTXO 合约执行链路构建具有工程完整性的解释性执行系统。其技术难度和工作量主要包括以下方面：

| 方面 | 具体难点 | 对应工作量 |
| --- | --- | --- |
| 执行模型设计 | 需要在 UTXO 交易上下文、合约参数、双栈虚拟机状态和高级语言语义之间建立清晰映射关系 | 梳理执行语义，设计运行时对象、环境、上下文和错误模型 |
| AST 解释执行 | 需要支持变量绑定、表达式求值、控制结构、函数调用和内置能力，并保持与语言语义一致 | 实现 RuntimeValue、RuntimeSlot、Environment、RuntimeContext、RuntimeError、BuiltinRuntime 等核心模块 |
| 字节码解释执行 | 需要模拟双栈虚拟机的指令执行、栈状态变化、异常处理和执行结果输出 | 完善 BVM 模拟器、非交互式运行能力、状态输出和命令行接口 |
| 交易上下文注入 | UTXO 合约执行依赖交易输入、输出、参数和上下文约束，本地执行需模拟链上输入环境 | 设计交易上下文输入格式、参数注入机制和典型合约运行样例 |
| 调试与可观察性 | 需要让开发者观察源码级和字节码级执行过程，而不仅是最终结果 | 集成 REPL、CLI 调试器、断点/单步执行/状态查看等能力，具体功能边界【待确认】 |
| 测试验证 | 需要证明系统能够正确执行典型合约并定位错误 | 构建回归测试、差分测试、典型合约测试和错误样例测试，具体测试数量、覆盖率和性能指标【待补充】 |

上述内容覆盖需求分析、系统设计、解释器核心实现、虚拟机模拟、调试交互、测试验证和论文撰写等环节，工作量符合专业学位研究生学位申请成果开题报告对工程实践深度、技术难度和成果可验证性的要求。

## 三、研究的创新之处

本课题的创新之处主要体现在面向 UTXO 双栈虚拟机执行场景，将高级语言解释执行、字节码执行模拟和调试观察能力整合到统一的软件工程系统中。与仅关注编译输出或链上执行结果的工具不同，本课题强调在合约部署前提供可观察、可追踪、可验证的本地解释执行链路。

第一，构建面向 UTXO 合约的双层解释执行机制。系统拟同时支持基于 AST 的源码级解释执行和基于字节码的双栈虚拟机执行，使开发者既能从高级语言层面理解变量绑定、表达式求值和控制流行为，也能从虚拟机层面观察指令执行、栈状态变化和运行错误。该机制有助于弥合高级语言语义与底层虚拟机行为之间的信息断层。

第二，设计交易上下文驱动的本地执行环境。UTXO 智能合约执行高度依赖交易输入、交易输出、解锁参数和验证条件。本课题拟在本地解释环境中引入交易上下文输入和参数注入机制，使合约能够在接近链上执行约束的条件下进行模拟运行。该设计有助于提前暴露交易构造错误、参数传递错误和合约验证逻辑不一致问题。

第三，增强智能合约执行过程的可观察性与调试能力。系统拟围绕 CLI 调试器、REPL、状态输出和错误报告构建交互式调试能力，使开发者能够查看运行时变量、栈内容、执行路径和错误位置。该设计将合约执行由“只给出最终成功或失败结果”扩展为“展示执行过程和失败原因”，符合工程调试工具对可解释性的要求。

第四，建立面向源码级与字节码级结果一致性的测试验证思路。课题拟通过典型合约样例、回归测试、差分测试和错误样例测试，对 AST 解释执行与字节码执行结果进行对比验证。该思路能够为解释器、编译器前端和双栈虚拟机之间的一致性检查提供基础，也为后续形式化验证或安全分析工具集成预留接口。

## 四、研究方法与技术路线

### 1. 研究目标

本课题拟设计并实现一套面向 UTXO 双栈虚拟机的智能合约解释性执行系统，形成从合约源码、抽象语法树、字节码到双栈虚拟机模拟执行的完整链路。系统应能够支持合约源码解析、语义检查、AST 解释执行、字节码生成、字节码解释运行、交易上下文注入、执行状态输出、交互式调试和测试验证等核心功能。通过该系统，开发者能够在部署前完成合约本地运行、错误定位和执行过程观察。

具体目标包括：第一，完善合约语言前端，使系统能够对典型 UTXO 智能合约样例进行词法分析、语法分析和抽象语法树构建；第二，设计运行时对象、作用域环境、交易上下文和错误处理机制，实现面向 AST 的源码级解释执行；第三，完善面向双栈虚拟机的字节码执行能力，实现指令执行、栈状态变化和运行结果输出；第四，设计交易上下文输入与参数注入机制，使本地运行能够模拟 UTXO 合约验证场景；第五，集成 CLI 调试器和 REPL，提供单步执行、状态查看、错误定位等调试能力，具体交互命令集合【待补充】；第六，通过测试样例和回归测试验证系统功能正确性和工程可用性。

### 2. 研究内容

本课题的研究内容围绕“语言前端、解释运行时、双栈虚拟机、交易上下文、调试工具和测试验证”展开。

第一，开展 UTXO 智能合约执行需求分析。结合原开题报告中的 UTXO_Interpreter 工程基础，分析智能合约从源码到执行结果的关键环节，明确系统输入、输出、功能边界和质量要求。输入主要包括合约源码、字节码文件、交易上下文文件和运行参数；输出主要包括执行结果、运行状态、错误信息、调试信息和测试报告。

第二，设计源码级 AST 解释执行模块。该模块以抽象语法树为输入，通过运行时值对象、变量槽位、作用域环境、运行上下文和内置函数机制完成表达式求值、语句执行、函数调用和错误处理。该部分重点解决高级语言语义如何在本地解释环境中被准确表示的问题。

第三，设计字节码级双栈虚拟机执行模块。该模块以字节码为输入，模拟双栈虚拟机中的指令执行、栈操作、状态转移和异常处理。该部分重点解决字节码执行过程可观察性不足的问题，并为调试器提供可读取的执行状态。

第四，设计交易上下文注入与参数绑定机制。该模块用于将 UTXO 合约执行所需的交易输入、交易输出、脚本参数和上下文信息注入运行环境，使合约能够在本地环境中接近真实链上验证条件运行。交易上下文的数据结构、输入格式和字段约束需在正式实现阶段结合现有工程进一步确认【待补充】。

第五，设计交互式调试与状态追踪功能。系统拟提供命令行执行、REPL 交互和调试器接口，使开发者能够查看当前执行位置、变量环境、栈状态、交易上下文和错误信息。调试能力的具体边界以工程实现为准，至少应覆盖典型错误定位和执行状态查看。

第六，构建测试验证体系。系统拟采用单元测试、集成测试、回归测试和典型合约样例测试，对词法语法分析、AST 解释执行、字节码运行、交易上下文注入和调试输出进行验证。若条件允许，应补充源码级执行结果与字节码级执行结果之间的一致性对比。

### 3. 拟采用的研究方法

本课题拟采用以下研究方法。

第一，文献调研与比较分析方法。通过梳理智能合约、UTXO 模型、双栈虚拟机、合约语言、解释器设计和软件验证相关研究，明确本课题的工程切入点和技术边界，并对账户模型智能合约工具链与 UTXO 智能合约工具链进行比较分析。

第二，模块化软件设计方法。按照编译器前端、运行时环境、虚拟机执行、交易上下文、调试交互和测试验证等模块划分系统结构，明确各模块输入输出、接口关系和异常处理方式，以降低系统耦合度并提升可维护性。
